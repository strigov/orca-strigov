`orca-dev` помогает создавать программы несколькими ИИ-моделями внутри
[Orca](https://orca.dev). Вы описываете, что должен уметь продукт. Система превращает запрос в
план, код, тесты и независимые ревью — и сохраняет доказательства выполненных проверок.

Проект рассчитан и на опытных инженеров, и **на вайбкодеров, которые умеют объяснить желаемый
результат, но пока не могут самостоятельно оценить архитектуру, тесты и детали реализации.** Он не
принимает продуктовые решения за вас, зато добавляет к вашему запросу дисциплинированный
инженерный процесс.

## Если совсем просто

Вы просите:

> Добавь восстановление пароля по почте. Ссылка должна жить 15 минут, а экран — хорошо выглядеть на телефоне.

Затем `orca-dev` координирует пять шагов:

1. **План** — одна ИИ-модель изучает проект и делит задачу на безопасные этапы.
2. **Реализация** — другая модель меняет код и пишет тесты.
3. **Проверка** — запускаются настоящие команды, а полные логи сохраняются.
4. **Ревью** — независимые семейства моделей ищут ошибки и рискованные допущения.
5. **Доставка** — принятая работа фиксируется в Git вместе с проверяемыми доказательствами.

Главное правило: **ИИ, который написал изменение, не остаётся единственным судьёй своей работы.**

## Подойдёт ли это мне?

`orca-dev` будет полезен, если вы узнаёте себя хотя бы в одном пункте:

- вы можете объяснить нужную функцию, но не уверены, что правильно проверяете сгенерированный код;
- обычный ИИ-чат иногда говорит «готово» раньше, чем действительно прошли все проверки;
- вы хотите подключить несколько моделей, не составляя отдельный промпт для каждой;
- вам важно знать, что именно запускалось, что прошло и что проверить не удалось;
- изменение затрагивает несколько файлов, платформ или этапов и не помещается в одну большую правку.

Это локальный процесс разработки, а не облачный no-code-сервис. Для первой настройки нужны Orca,
Git и перечисленные ниже CLI моделей. После настройки обычная работа начинается с запроса на
человеческом языке.

## Установка

### 1. Установите необходимые программы

Вам понадобятся:

- [Orca](https://orca.dev) с включённой оркестрацией;
- Git 2.36 или новее;
- Codex CLI, Claude Code и Antigravity CLI (`agy`) для стандартных рабочих ролей;
- macOS/Linux: Bash 3.2+, Python 3.9+ на Linux или Python 3.13+ на macOS;
- нативная Windows: PowerShell 5.1 или 7. Runtime-инструментам Python не нужен.

Перед работой нужно один раз войти в аккаунт в каждом CLI модели. Установщик проверит настройку и
покажет понятные строки `OK`, `INFO` или `WARN`. Он не обновляет программы и не меняет посторонние
настройки системы.

### 2. Скачайте правильный ZIP

Самый простой способ не требует команд Git:

1. Откройте [последний релиз](https://github.com/strigov/orca-strigov/releases/latest).
2. Раскройте раздел **Assets**.
3. Скачайте **`orca-dev-<версия>.zip`**. Не выбирайте автоматический архив GitHub “Source code”.
4. Распакуйте его в постоянную папку, например `Documents/orca-dev`. Установленный навык будет
   ссылаться на эту папку, поэтому не удаляйте и не переносите её без повторной установки.

В каждом релизе также есть `orca-dev-<версия>.zip.sha256` для проверки скачанного файла.

### 3. Запустите установщик

macOS, Linux или WSL2 — откройте Terminal в распакованной папке:

```bash
./install.sh
./install.sh --repo /путь/к/вашему/проекту
```

Нативная Windows — откройте PowerShell в распакованной папке:

```powershell
.\install.ps1
.\install.ps1 -Repo C:\путь\к\вашему\проекту
```

Вместо примера укажите папку приложения, которое хотите разрабатывать. Вторая команда разрешает
рабочим CLI открывать этот проект и его Git worktree. Выполните её один раз для каждого проекта.

Если Windows блокирует запуск скрипта, точная команда PowerShell и вариант с WSL2 описаны в
[руководстве по установке на Windows](docs/install-windows.md).

### 4. Убедитесь, что всё готово

Эти команды ничего не изменяют:

```bash
./install.sh --check /путь/к/вашему/проекту
```

```powershell
.\install.ps1 -Check C:\путь\к\вашему\проекту
```

- `OK` — всё готово;
- `INFO` — полезная справка, действий не требуется;
- `WARN` — эту проблему нужно решить до начала работы.

Пока остаются предупреждения, команда завершается с кодом `1`, поэтому неполная настройка не
выглядит как успешная.

<details>
<summary><strong>Предпочитаете Git? Установка из репозитория</strong></summary>

macOS, Linux или WSL2:

```bash
git clone https://github.com/strigov/orca-strigov.git ~/orca-strigov
cd ~/orca-strigov
./install.sh
./install.sh --repo /путь/к/вашему/проекту
```

```powershell

cd $HOME\orca-strigov
.\install.ps1
.\install.ps1 -Repo C:\путь\к\вашему\проекту
```

Выбирайте этот путь, если хотите обновляться через `git pull` или участвовать в разработке.

## Первый запуск

1. Откройте репозиторий своего приложения в Orca.
2. Запустите в нём **Codex terminal**.
3. Опишите результат обычными словами:

```text
Реализуй восстановление пароля. Оно должно работать по почте, ссылка должна
истекать через 15 минут, экран — хорошо выглядеть на телефоне. Добавь тесты
и обнови инструкцию для пользователя.
```

Запросы на реализацию активируют `orca-dev` автоматически. Навык можно вызвать и явно:

```text
$orca-dev Реализуй восстановление пароля с тестами и документацией.
```

В Orca будут появляться рабочие терминалы. Координатор сообщает о важных переходах и обращается к
вам только тогда, когда нужно продуктовое решение, отсутствующий доступ или новое разрешение.

### Как написать хороший запрос без инженерных терминов

По возможности укажите четыре вещи:

- **кто** будет пользоваться функцией;
- **что** этот человек должен суметь сделать;
- **чего не должно произойти**;
- **как выглядит успешный результат**.

Например: «Клиент может выгрузить свои счета в CSV. В выгрузку не должны попасть данные другого
клиента. Кнопка находится на странице оплаты, рядом нужна короткая подсказка». Автор плана сам
переведёт это в технические шаги и вынесет недостающие решения на обсуждение.

## От каких ошибок защищает протокол

Успешного теста недостаточно, если он запускался не на тех файлах. Ревьюер не может одобрять код
своего семейства моделей. Тайм-аут не доказывает, что исполнитель остановился. `orca-dev` фиксирует
версию исходников, команды, логи, ревью и владельцев работы, чтобы типичные ошибки нескольких
ИИ-агентов не исчезали внутри уверенного резюме.

<details>
<summary><strong>Роли и инженерные ограничения</strong></summary>

| Роль | Задача |
| --- | --- |
| Координатор | Распределяет работу, сверяет доказательства и ведёт Git |
| Автор и ревьюер плана | Создают и независимо проверяют план реализации |
| Исполнитель | Меняет код и тесты в рамках одного разрешённого этапа |
| Gate | Запускает заданные проверки и сохраняет полные доказательства |
| Primary / control reviewer | Независимо проверяют одну и ту же поставку |
| Диагност | Исследует блокеры, не расширяя задачу молча |
| Финальный ревьюер | Проверяет всю ветку перед доставкой |

У циклов исправления и ревью есть явные лимиты. Точная матрица моделей, усилий, fallback-маршрутов
и независимости находится только в [`skills/orca-dev/roles.md`](skills/orca-dev/roles.md).

</details>

## Поддержка платформ

| Платформа | Runtime | Текущие доказательства в репозитории |
| --- | --- | --- |
| Linux | Bash + Python 3.9+ | Интеграционный набор Ubuntu в GitHub Actions |
| macOS | Bash + Python 3.13+ | Нативный сценарий macOS CI и проверки возможностей |
| Windows | Нативный PowerShell 5.1/7 | Отдельные задания Windows PowerShell и `pwsh` |
| WSL2 | Linux-путь внутри дистрибутива | Инструменты поддерживаются; доступность Orca и model CLI зависит от среды |

Точные доказательства и ограничения описаны в [контракте платформ](docs/runtime-platforms.md) и
[отчёте управляемого конвейера](docs/controlled-pipeline-validation.md). Исторические smoke-тесты —
наблюдения, а не текущая сертификация.

## ZIP-архивы релизов

Публикация GitHub Release запускает [release workflow](.github/workflows/release.yml), который
прикрепляет:

```text
orca-dev-<версия>.zip
orca-dev-<версия>.zip.sha256
```

В ZIP входят установщики, runtime-инструменты, файлы навыка и пользовательская документация. Тесты,
исторические планы и эксперименты остаются в исходном репозитории и намеренно исключены.

## Структура репозитория

```text
skills/orca-dev/       протокол, матрица ролей, рабочие промпты и контракты
bin/                   POSIX- и PowerShell-инструменты runtime
docs/                  установка, платформы, проверки и исторические свидетельства
tests/                 изолированные интеграционные и служебные тесты
install.sh             установщик для macOS, Linux и WSL2
install.ps1            установщик для нативной Windows
assets/readme/         графика для GitHub README
```

Знакомство с внутренним протоколом лучше начать с
[`skills/orca-dev/SKILL.md`](skills/orca-dev/SKILL.md).
