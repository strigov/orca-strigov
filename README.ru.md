# Ваша задача. Команда агентов. Проверенный код.

**orca-strigov** — самостоятельный скилл разработки для Codex и Claude Code, который превращает задачу разработки в управляемый процесс внутри [Orca](https://orca.dev). Координатор раздаёт работу агентам, запускает проверки проекта и отправляет изменения на два последовательных ревью перед коммитом.

Вы описываете результат. Скилл `orca-dev` организует подготовку спецификации и плана, фазы реализации, исправления и передачу работы между агентами.

|---|---|

| **Проверки после реализации** | Координатор изучает diff и запускает команды проверки. |

| **Видимый прогресс** | Завершённые фазы становятся Git-коммитами; итоговый отчёт связывает результат с критериями приёмки. |
| **Ограниченные циклы исправлений** | У раундов есть лимит, о смене модели сообщают, а нерешённые вопросы возвращаются к вам. |

## Быстрый старт

### 1. Установите скилл для своего агента

Нужны **Python 3.9+** и **Git**. Клонируйте репозиторий и установите одну или обе версии:

```sh
git clone https://github.com/strigov/orca-strigov.git
cd orca-strigov
python3 skills/orca-dev/scripts/install.py --agent codex --agent claude
```

Если нужен только один агент, оставьте один параметр `--agent`. При переходе с плагина сначала выполните [шаги миграции](#переход-с-плагина), чтобы сохранить активную работу. Установка копирует самостоятельный комплект скилла; запущенная Orca не требуется, настройки доверия к проектам не меняются.

| Агент | Каталог установки | Вызов |
|---|---|---|
| Codex | `~/.codex/skills/orca-dev` (или `$CODEX_HOME/skills/orca-dev`, если переменная задана) | `$orca-dev` |
| Claude Code | `~/.claude/skills/orca-dev` | `/orca-dev` |

**Обновление:** повторите команду установки из обновлённого исходника. Распознанная установка заменяется, включая ваши правки внутри поставляемых файлов; перед обновлением сохраните их отдельно. Симлинки, нераспознанные каталоги и копии с файлами или симлинками, которых нет в новой версии, не перезаписываются: установщик перечислит мешающие записи. Установщик печатает итоговый путь и не создаёт вторую копию в `~/.agents/skills`.

### Готовые архивы

В [релизе v2.1.0](https://github.com/strigov/orca-strigov/releases/tag/v2.1.0) доступны отдельные [ZIP для Codex](https://github.com/strigov/orca-strigov/releases/download/v2.1.0/orca-dev-codex-v2.1.0.zip) и [ZIP для Claude Code](https://github.com/strigov/orca-strigov/releases/download/v2.1.0/orca-dev-claude-v2.1.0.zip). Распакуйте нужный архив и выполните `python3 orca-dev/scripts/install.py --agent codex` (или `--agent claude`). Каждый ZIP содержит одну папку `orca-dev/` со всеми нужными файлами.

Ветка [release](https://github.com/strigov/orca-strigov/tree/release) содержит те же подготовленные скиллы в `codex/orca-dev/` и `claude/orca-dev/`, а её README — исходный коммит. Можно клонировать её командой `git clone --branch release --single-branch https://github.com/strigov/orca-strigov.git` и из её каталога выполнить `python3 codex/orca-dev/scripts/install.py --agent codex` или `python3 claude/orca-dev/scripts/install.py --agent claude`.

### 2. Подготовьте Orca и CLI исполнителей

Для **запуска процесса разработки** нужны работающая **Orca 1.4.224+**, Git и CLI `codex`, `claude`, `agy` с выполненным входом в аккаунты для выбранных моделей. Python-утилиты используют только стандартную библиотеку.

Установите штатные скиллы Orca:

```sh
orca skills install --skill orchestration --skill orca-cli --agent codex,claude-code
```

### 3. Проверьте окружение и настройте доверие к проекту

В каталоге исходников подставьте путь к репозиторию, **в котором будут работать агенты**:

```sh
python3 skills/orca-dev/scripts/install.py --repo "/absolute/path/to/your-project"
```

Режим `--repo` проверяет окружение и настраивает доверие к проекту и его Git-worktree. Настройки доверия записываются только в `~/.claude.json`, `~/.gemini/antigravity-cli/settings.json` и `~/.codex/config.toml`. Если файла настроек ещё нет, один раз запустите соответствующий CLI и повторите команду. Для скачанной или установленной копии используйте её собственный путь к `scripts/install.py`.

Для проверки окружения без изменений запустите установщик без аргументов. Добавьте `--check "/absolute/path/to/your-project"`, чтобы также проверить доверие к проекту без записи настроек. Код выхода `1` означает, что есть предупреждения. `--check` нельзя совмещать с установкой или сборкой.

<details>
<summary><strong>Установка на Windows</strong></summary>

Используйте PowerShell и замените `python3` на `py -3`:

```powershell
py -3 skills/orca-dev/scripts/install.py --agent codex --agent claude
py -3 skills/orca-dev/scripts/install.py --repo "C:\path\to\your-project"
```

Указывайте абсолютные Windows-пути к проектам. Если в нативной Windows нет `agy`, исполнителем станет Codex Luna. Работа `agy` в нативной Windows не проверена.

</details>

### 4. Передайте задачу координатору

После установки начните новую сессию агента. В **чате Codex**:

```text
$orca-dev исправь отображение пустого списка задач
```

В **чате Claude Code**:

```text
/orca-dev добавь экспорт отчёта в CSV
```

Скилл запускается **только по явному вызову**. Обычное сообщение в чате его не активирует; агенты-исполнители следуют своим заданиям.

## Как это работает

### Небольшая задача → быстрый путь

Если по оценке нужно изменить **не больше двух файлов кода**, без изменений схем, миграций, безопасности и публичного API:

```text
Реализация → Проверки → Ревью Opus → Ревью Astra → Коммит
```

Слияние уже принятых веток тоже проходит по быстрому пути. Отдельные спецификация и план не создаются.

### Большая задача → спецификация и фазы

```text
Спецификация → Ваше «ок» → План → Фазы реализации → Итоговое ревью
                                 └ каждая фаза: код → проверки → Opus → Astra → коммит
```

1. **Согласовать результат.** Opus пишет спецификацию, Astra её проверяет. Вы утверждаете критерии приёмки ответом «ок» до начала планирования.
2. **Разбить работу на фазы.** Opus готовит план, Astra проводит ревью. У каждой фазы есть свои критерии и команды проверки.
3. **Реализовать и проверить.** Агент выполняет фазу по инструкциям TDD из задания; координатор изучает diff и запускает проверки.
4. **Провести два ревью.** Opus проверяет выполнение критериев, затем Astra оценивает качество кода. Блокирующие замечания запускают исправления и новый цикл ревью.
5. **Зафиксировать результат.** Принятые фазы коммитятся. Итоговое ревью Opus сверяет всю работу со спецификацией.

**Управление остаётся у вас.** После успешного ревью коммиты создаются автоматически, если вы не отключили автокоммит в задаче. Попросите сначала показать план, если хотите ещё одну точку согласования. При исчерпании лимита исправлений или нерешённых блокерах координатор предложит выбор: принять результат, разрешить ещё раунд или остановиться.

**Чтобы продолжить большую задачу,** вызовите `orca-dev` и укажите путь к плану или его короткое имя — slug. Координатор восстановит контекст по плану, истории Git и состоянию запуска в Orca. Задачи быстрого пути запускаются заново.

## Команда

В скилле заданы фиксированные пресеты моделей. Источник истины для моделей, уровней усилия и правил замены — [roles.md](skills/orca-dev/roles.md).

| Задача | Основная модель | Уровень усилия / замена |
|---|---|---|
| Написать спецификацию и план | Claude `opus` | `xhigh`; доработки на `high` |
| Проверить спецификацию и план | Codex `gpt-6-astra` | `xhigh` |
| Backend и реализация по быстрому пути | Antigravity `gemini-3.8-flash-high` | При недоступности: Codex `gpt-6-luna` на `max` |
| Сложные фазы и однократная эскалация | Codex `gpt-6.1-sol` | `high` |
| Frontend | Claude `opus` | `high`; для фаз до двух файлов — `sonnet` на `medium` |
| Проверка требований и итоговое ревью | Claude `opus` | `high`; ревью рискованной фазы или последнего раунда — на `xhigh` |
| Проверка качества кода | Codex `gpt-6-astra` | `high` |

Порядок ревью всегда **Opus → Astra**. Ревьюеры не заменяются автоматически. На исправления отводится до трёх раундов, затем возможна одна эскалация на Sol с ещё тремя раундами; если фаза началась на Sol, дальнейшей эскалации нет.

## Один исходник, две версии для агентов

Orca управляет запусками, задачами, передачей заданий и жизненным циклом агентов. Скилл добавляет процесс разработки, выбор моделей, шаблоны заданий и утилиту запуска. В составе — **один скилл**, **два Python-файла**, **без хуков и отдельной машины состояний**.

```text
skills/orca-dev/
├── SKILL.md          Правила работы координатора
├── roles.md          Модели, уровни усилия, замены
├── launch.md         Запуск агентов и работа с терминалами
├── prompts/          11 шаблонов заданий
└── scripts/
    ├── orca_dev.py   Подготовка заданий, запуск, готовность, закрытие
    └── install.py    Установка, сборка, проверки окружения, доверие к проекту
tests/                Тесты на стандартной библиотеке Python
```

Обе версии используют общий процесс. Версия для Codex содержит `agents/openai.yaml` с `allow_implicit_invocation: false`; версия для Claude Code — `disable-model-invocation: true` во frontmatter. Обычное сообщение не запускает скилл автоматически.

**Сборка релизных архивов:** в каталоге исходников выполните `python3 skills/orca-dev/scripts/install.py --bundle /absolute/path/to/output`. Каталог результата должен отсутствовать или быть пустым и находиться вне папки исходного скилла. Этот отдельный режим создаёт обе версии и ZIP-архивы без проверок окружения и изменений доверия.

## Переход с плагина

**Завершите активные задачи координатора до изменения установки.** Работающий координатор или обёртка запуска воркеров могут импортировать утилиты из старого кэша плагина или checkout. Сохраняйте эти файлы, пока все использующие их задачи не закончатся.

1. Установите самостоятельную версию для нужного агента командами выше.
2. Удалите старый плагин Codex командой `codex plugin remove orca-strigov@personal`; она также удаляет его локальный кэш.
3. Проверьте оставшиеся предупреждения о старых копиях и удалите только подтверждённые остатки этого скилла. Установщик перечисляет старые копии, но не очищает их автоматически.
4. Начните новую сессию агента и убедитесь, что доступен один актуальный `orca-dev`.

Исторические архивы v2.0.0 остаются доступны. Текущая поставка не содержит манифестов плагина, хуков, квитанций, журналов состояния и встроенных штатных скиллов Orca.
