# Audit 2026-09-02 — protocol text, prompts, scripts

Three independent read-only audits (protocol docs, role prompts, bash tooling) after the third smoke run, ≈110 findings. This file records what was changed and what was deliberately left. Line references are to the pre-audit tree (`8343db0`).

## Fixed

### Protocol (`SKILL.md`, `roles.md`, `orca-recipes.md`)
- **Terra escalation in Luna's terminal was impossible** (`--model` cannot be combined with `--terminal`; Path B bakes the model into argv). A model escalation is now always a fresh terminal with the fresh-fallback re-brief plus the BLOCKED and diagnosis reports.
- **Family rule broke after a cascade** (Luna-written code reviewed by Sol; Claude-written frontend reviewed by Opus). New `Family-rule substitutions` table in `roles.md`; 4.2 falls to Fable when the implementer was a Codex model; frontend phases get Sol/Terra reviewers and a Sol final review.
- **`diagnosis` role had no template and no tokens.** Added `prompts/diagnosis-prompt.md` and the verdict row `NEEDS_MORE_CONTEXT | NEEDS_MORE_REASONING | PHASE_TOO_LARGE | PLAN_WRONG | IMPASSE_SUMMARY`; Step 3 branches on the token, `escalation` messages are handled like `BLOCKED`.
- **Parallel tracks both edited the plan frontmatter** (merge conflict by construction; run 2 survived only because the hunks were identical). A track never touches the plan file; both flips happen in the main tree at group step 6.
- **Step 5 merge base was empty on `main`.** `plan_base:` is recorded in the frontmatter at the plan commit and is the final-review base; `merge-base main HEAD` is a fallback off `main` only; an `EMPTY` package is an error.
- **BASE did not survive compaction.** Step 3.1 writes per-phase `base:`; resume goes through 3.5 before 4.
- **Auto-commit skip started the next phase on a dirty BASE.** After a skipped commit the coordinator stops and reports.
- **Plan-less frontend path** (skip Steps 1–2) removed; **quickfix path** now defined (branch check, `--name` workspace, no diff read, commit by `--files-modified`).
- **Pre-flight gate forbade the commands needed to leave it**; the allowed list now includes task-create/worker-start/dispatch/terminal create and `install.sh --repo`.
- Gate-fix rounds and integration repairs have a ledger id (`G<r>-B<n>`, reviewer `gate`) and reuse the fix-round template; Step 5 and integration repairs re-run the gate before re-review.
- 20-minute idle rule moved into Step 3; `accept-at-escalation` defined; `risk:` per phase (`none | SECURITY | DATA_LOSS | REGRESSION`) added to the plan frontmatter and to the 2.5 checks; `PLAN_FAIL` removed; Sonnet effort and the Luna-medium synthesizer fallback added to the cheat-sheets; model names removed from the SKILL body (roles.md is the only place).
- State line gained `quickfix | 4.6-integration | 5-fix`; frontmatter description shortened.

### Prompts
- Gate template no longer tells the worker to `git stash` an uncommitted implementation (throwaway `git worktree add` at BASE instead).
- Plan writer no longer writes reviewer-directed sentences into the plan body (the anti-coaching scan only covers the spec); `risk:` added to the frontmatter example.
- `SYNTHESIS_DONE` and `NEEDS_AUTHORIZATION` are bare tokens on line 1 (path / details on line 2 and in the body).
- Fix rounds may return `NEEDS_CONTEXT`; the frontend fix round has the same scope rules as the backend one; "reviewers will not re-run the suite — your report is the evidence" removed from the implementer side.
- `ask --timeout-ms 600000` (longer than any worker's shell-tool timeout) → 90 s with `--resume <message_id>` retries.
- `CANNOT_VERIFY` `CHECK:` is always a shell command; "tree is green" assertions replaced by "read the gate summary literally"; control review no longer pre-frames `REVIEW_OK`; control review carries a repo-root line; final review no longer contradicts itself about git commands; quickfix no longer asks the coordinator to "sanity-check the diff".

### Scripts
- `verify-gate`: false `GATE_OK` paths closed — command-not-found and 0-passed can never be green; verify commands get `</dev/null`; YAML block scalars, trailing comments after quoted items and flow-style quoting handled; summary-line counts no longer normalized away; BSD sed compatibility; explicit errors for a missing `python3` and a failed BASE checkout; inherited classification is downgraded to `NEEDS_JUDGMENT` when a shared `.venv`/`node_modules` could execute HEAD sources.
- `review-package`: an empty package (0 commits / 0 hunks) is reported as `EMPTY` with exit 1; WORKTREE mode warns when it embeds many/large untracked files.
- `wait-agent-ready`: failing Orca reads are distinguished from a slow agent; the marker is scanned only in the last 25 lines; timeout validated.
- `sdd-workspace`: `pwd -P`; `--name <slug>` for plan-less (quickfix) workspaces.
- `install.sh`: zero trusted hooks is a WARN (was a false OK); bad or missing path arguments fail fast; `pwd -P`; git worktrees of the repo are trusted too; `--repo` repeatable; JSON written atomically, missing/invalid files reported; never `rm -rf` a real directory; exit 1 on any WARN (informational lines are `INFO`).

### Docs
- README status and layout, `docs/smoke-runs.md` (all three runs), `phase2-smoke.md` superseded note, AGENTS.md layout.

## Left as is (with reasons)
- Duplicated Reporting blocks in every template (~180 tokens each): the Orca preamble does not reliably carry the `send` line for Path B workers, and the duplication has not caused a failure in three runs.
- Per-template token budgets and moving SKILL.md sections into reference files: deferred until a run shows the coordinator dropping rules; splitting the hot path is its own risk.
- `install.sh --repo` for worktrees created *after* the install: covered by the parallel-group step, not by the installer.
- No fallback when Sol is unavailable for plan review (a Codex-family reviewer is required by the family rule when Opus revised); the coordinator escalates to the user.
- Everything above is untested in a live run — the next smoke run should be on a repo with a real venv and a deliberately failing verify command.
