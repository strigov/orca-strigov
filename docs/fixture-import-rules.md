# Правила импорта CSV в todo-fixture

Относится к команде `import PATH` модуля `spikes/fixture/todo_export.py`.

## Вход

- CSV в UTF-8 с обязательной строкой заголовка ровно `id,text,done` (тот же формат, что пишет `todo_export.py`).
- `id` — целое число ≥ 1; `text` — любая строка (пустая допустима); `done` — ровно `True` или `False`.
- Строки после заголовка проверяются **все до записи**; хранилище меняется только если файл валиден целиком.

## Слияние по `id`

- `id` уже есть в хранилище → у существующего элемента заменяются `text` и `done` значениями из CSV; позиция элемента не меняется.
- `id` в хранилище нет → элемент добавляется с этим `id` (переназначение `id` запрещено); новые элементы дописываются в конец в порядке строк CSV.
- Элементы хранилища, которых нет в CSV, не изменяются и не удаляются.
- Один и тот же `id` несколько раз в CSV → побеждает последняя строка.

## Ошибки

- Отсутствующий или нечитаемый `PATH`, неверный заголовок, неверное число колонок, нецелый или < 1 `id`, `done` не из `{True, False}` → код возврата `2`, ровно одна строка в stderr с номером первой невалидной строки (заголовок — строка 1), stdout пустой, хранилище байт в байт не изменено.

## Успех

- Код возврата `0`; в stdout — по одному `repr(dict)` на строку для каждого добавленного или обновлённого элемента в порядке строк CSV (как печатает `todo.py`); пустой CSV (только заголовок) → ничего не печатает, хранилище не переписывается.
- Запись — через тот же слой хранения, что и изменяющие операции `todo.py` (атомарная замена temp+rename и межпроцессная блокировка, если она введена); `import` не должен дублировать логику сериализации.
